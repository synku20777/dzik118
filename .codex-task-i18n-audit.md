# QA audit: i18n translation coverage (Latvian / Russian)

Read-only audit. Do not edit any files. Report findings only.

## Context

`src/lib/ui/i18n.ts` exports `translate(locale, text)` which does
`lv[text] ?? text` / `ru[text] ?? text` — a silent fallback to raw English on
any missing dictionary key. Two `Record<string, string>` dictionaries `lv`
and `ru` hold translations, populated from strings used across
`src/pages/admin/**/*.astro` and `src/components/ui/**/*.astro` via `t(...)`
calls (direct literals AND indirect strings stored in array/object literals
then passed through `t(...)` later, e.g. `guide/index.astro`'s `setupSteps`,
`monthlySteps`, `faqs`, `statuses` arrays).

A translation-coverage pass was just completed by hand (137 new key/value
pairs added across two batches) after two Antigravity CLI dispatch attempts
failed to produce any file changes.

## Your task

1. Find every distinct English string that reaches `translate()` at runtime
   across `src/pages/admin/**/*.astro` and `src/components/ui/**/*.astro`.
   This includes:
   - Direct calls: `t("...")`, `t('...')`, `translate(locale, "...")`.
   - Indirect calls: a string literal stored in a local array/object (e.g.
     `const statuses = [["CODE", "Some description", "variant"], ...]` or
     `const steps = [{ title: "...", description: "...", ready: "...",
     action: "...", imageAlt: "..." }, ...]`) that is later passed through
     `t(...)` in the template (e.g. `t(step.title)`, `t(row[1])`).
   - Ternary/ conditional string arguments: `t(condition ? "A" : "B")`.
2. Diff that full set of strings against the keys of the `lv` and `ru`
   dictionaries in `src/lib/ui/i18n.ts`.
3. Report every English string still missing a Latvian key and/or a Russian
   key (there should be none — confirm zero, or list exactly what's missing).
4. Spot-check translation quality: read ~15 translated entries from each
   dictionary at random (mix of short labels and long sentences) and flag
   any that are mistranslated, awkward, or inconsistent with terminology used
   elsewhere in the same dictionary (e.g. the same English term translated
   two different ways).
5. Check for orphaned keys in `lv`/`ru` (a key present in the dictionary that
   no longer matches any string used in the codebase) — report but do not
   treat as urgent, since removing them is optional cleanup.
6. Run: `npm run typecheck`, `npx astro check` (astro:check script if
   present), `npx prettier --check src/lib/ui/i18n.ts`. Report pass/fail for
   each. Note: astro:check may report an unrelated sandbox error about
   `[astro] Unable to load your Astro config` / `require is not defined` in
   `node_modules/source-map-js` — this is a known environment artifact, not a
   real bug; if you see ONLY that error, say so explicitly rather than
   reporting it as a finding.

## Output

Plain text report:
- Coverage: PASS (zero missing) or FAIL (list every missing string with its
  source file/line).
- Quality spot-check: list any flagged translations with the English source,
  the flagged lv/ru text, and why it's flagged. If none, say "no issues
  found in sample."
- Orphaned keys: count and a short list (or "none").
- Gate suite: pass/fail per command.
